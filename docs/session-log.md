# Mention — build & launch log

Working record of the founding build session (31 Oct – 1 Nov 2026).
Repo: https://github.com/Sticksimsai/mention · Live: https://getmentions.xyz (web) · https://api.getmentions.xyz (api)

## What Mention is

Social trading on Solana. Every token launched mints its own community — an
X-style feed mirrored with X in both directions:
- **X → site:** tweets mentioning a community's `$TICKER`/CA are pulled in via SocialData.
- **Site → X:** posts can publish to the author's real X account (official X API, `tweet.write`).
- **Launchpad:** launching on pump.fun (through the platform wallet) is the only way a community is created.

Rebranded from the v1 project "Tribes" (Supabase/Lovable build that suffered
overload/downtime from edge-function sync jobs).

## Architecture (v2)

pnpm monorepo:
- `apps/api` — Hono (Node) REST API. Privy JWT auth, communities/posts/merged feed,
  roles (admin/mod/owner/banned), token stats (Redis-cached, DexScreener + pump.fun
  fallback), search, top-10 mcap, X OAuth write-back, launchpad, trade building, admin.
- `apps/worker` — BullMQ workers + scheduler: per-user tweet sync (dormancy tiers,
  SocialData daily spend cap), X write-back poster (token refresh), token-stats
  warming (30s), trending (5m).
- `apps/web` — Next.js 14. Home = live "For you"/"Joined" feed + trending cards,
  Explore, Leaderboard (live mcap top table), Launchpad, Docs, community pages
  (mcap pulse banner, chart, trade tab), profile, settings, admin.
- `packages/db` — Drizzle schema (v1's 53 Supabase migrations consolidated), migrations.
- `packages/shared` — types, zod schemas, queue names.

Reliability design: persistent services (no cold starts), every external call in a
retryable queue job with concurrency caps, Redis cache with stale-on-error on all
hot paths, counts updated in DB transactions, global SocialData kill-switch cap.

## Fee model (decided)

- Tokens launch with the platform wallet as pump.fun creator → creator fees on all
  volume accrue to platform, split with launcher (pump.fun supports 10-wallet split;
  launcher wallet + `platform_fee_share_bps` stored per community).
- Pump.fun current rates: 0.30% creator on bonding curve; post-graduation tiered —
  0.95% above ~420 SOL mcap stepping down to 0.05% above ~98k SOL.
- In-app trades add `PLATFORM_TRADE_FEE_BPS` (1%) to PLATFORM_FEE_WALLET.
- Alternatives analysed in `docs/fee-options.md` (PumpSwap-direct LP capture = Option B;
  own bonding curve = Option C, later).
- Main-token config: creator = platform wallet, no Holder Rewards/Cashback, canonical
  pool only, no ownership transfer, claim via pump.fun profile → Creator rewards.

## Custody decisions

- **No custodial third parties.** PumpPortal Lightning (custodial) was removed;
  launches use PumpPortal's keyless `trade-local` endpoint as a tx builder only,
  signed server-side by `PLATFORM_WALLET_SECRET` (self-custodied), sent via own RPC.
- User trades: non-custodial (unsigned tx built server-side + platform fee
  instruction; signed in the user's own wallet).
- X OAuth tokens: AES-256-GCM at rest (key derived by SHA-256 from `TOKEN_ENCRYPTION_KEY`).

## Env keys & where they come from

| Key | Source | Status at log time |
|---|---|---|
| PRIVY_APP_ID/SECRET, NEXT_PUBLIC_PRIVY_APP_ID | dashboard.privy.io (enable Twitter login; allow domain) | set |
| TOKEN_ENCRYPTION_KEY | auto-generated by Render | set |
| SOCIALDATA_API_KEY | socialdata.tools | pending |
| X_CLIENT_ID/SECRET | developer.x.com OAuth2 app (Read+Write; callback `https://api.getmentions.xyz/v1/x/callback`; pay-per-use ~$0.015/post) | pending |
| PLATFORM_WALLET_SECRET | self-made keypair (Phantom export base58 or solana-keygen JSON); fund ~0.2 SOL; sweep regularly | pending |
| PLATFORM_FEE_WALLET | public address receiving in-app trade fees | pending |
